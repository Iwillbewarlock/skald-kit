# Skald: instructions for applying this design

This file is written for AI coding assistants (ChatGPT, Codex, Claude, Gemini, Copilot) and for human readers. Read all of it before changing any file. It tells you what Skald is, which files to copy, how to restyle an existing mod UI, and what to check before you finish.

## What Skald is

Skald is a dark UI design that looks like Skyrim's own menus: smoky near-black grounds, thin pale 1px lines, square corners, wide-tracked capital titles and quiet colours. It comes from the spell panel of the Heart of Magic mod and works for any HTML/CSS interface.

## Where it applies

| UI technology | What you can use |
| --- | --- |
| HTML/CSS in game (PrismaUI, other Ultralight-based UIs), web pages, launchers, tool front-ends | Everything: `skald-tokens.css`, `skald.css`, the ornaments |
| Scaleform / SkyUI menus (SWF, ActionScript) | CSS is not supported there. Use the values in `skald-tokens.json` (colours, sizes, spacing) inside the Flash/ActionScript code and follow the rules below by hand |
| Qt (Mod Organizer 2 plugins), ImGui, other toolkits | Same as Scaleform: take the values from `skald-tokens.json` and follow the rules |

If the user's UI is not HTML/CSS, say so before you start and apply only the values and rules.

## Files

| File | What it is |
| --- | --- |
| `skald-tokens.css` | Every colour, spacing step, line width, radius and font as a CSS variable on `:root`, plus `.sk-type-*` text classes. Generated; do not edit by hand. |
| `skald.css` | The component classes (`sk-btn`, `sk-tab`, `sk-textfield`, `sk-dialog`, ...). Needs `skald-tokens.css` loaded first. |
| `skald-tokens.json` | The same values as plain data, for code that is not CSS. |
| `assets/corner.png` | Knotwork corner ornament, 200 x 200, transparent. |
| `assets/empty.png` | Empty-screen plate with the five magic school marks, 480 x 320, transparent. Heart of Magic specific. |
| `demo.html` | Every component on one page. Open it in a browser to see the target look. |

## Install

1. Copy `skald-tokens.css`, `skald.css` and the `assets` folder next to the mod's HTML (or into its styles folder). Keep the relative paths of the images if you use them.
2. Load the two stylesheets in this order, after the mod's own stylesheets so Skald wins where both style the same thing:
   ```html
   <link rel="stylesheet" href="skald-tokens.css">
   <link rel="stylesheet" href="skald.css">
   ```
3. Put the class `sk-root` on the element that wraps the whole UI (often `body` or the panel's outer `div`). It sets the background, text colour, font, Korean line breaking and the focus ring.

## Two ways to restyle an existing UI

Pick one and tell the user which approach you chose.

**A. Add Skald classes to the markup** (best when you can edit the HTML). Add the Skald classes from the component table below next to the mod's own classes on buttons, inputs, tabs and dialogs. Do not remove the mod's classes or IDs: scripts often find elements by them. Remove or override the mod's old styling for those elements wherever it conflicts with Skald.

If the mod marks a state with its own class instead of the ARIA attribute Skald uses (for example `.active` on a tab instead of `aria-selected="true"`), keep the mod's class and give it the same look in a small extra rule:

```css
.my-tabs .my-tab.active { background: var(--wash-14); color: var(--text-strong); border-bottom-color: var(--accent); }
```

**B. Map the mod's selectors to Skald variables** (best when the markup is generated by script or must not change). Write one extra stylesheet, loaded last, that restyles the mod's existing selectors using only Skald variables:

```css
/* skald-override.css: the mod's own selectors, Skald's values */
.my-panel        { background: var(--bg); color: var(--text); font-family: var(--font-skald); border: 1px solid var(--border); border-radius: 0; box-shadow: none; }
.my-panel h1     { font-size: 30.4px; font-weight: 400; letter-spacing: 5px; text-transform: uppercase; color: var(--text-strong); }
.my-button       { background: transparent; border: 0; border-bottom: 1px solid var(--border); border-radius: 0; color: var(--text); padding: 8px 14px; }
.my-button.main  { color: var(--text-strong); border-bottom-color: var(--accent); }
.my-input        { background: var(--well); border: 1px solid var(--border-control); border-radius: 0; color: var(--text); padding: 6px 10px; }
.my-tab.active   { background: var(--wash-14); color: var(--text-strong); border-bottom: 2px solid var(--accent); }
```

In both cases, never hard-code a Skald colour in the mod's files; use the colour variables so all colours stay in one place. Sizes with no variable (font sizes, letter spacing, the 14px button padding) may be written as numbers.

Loading Skald last does not beat everything: a more specific selector (`#panel .btn`) or an inline `style` in the mod still wins. Where that happens, write the override with the mod's own, equally specific selector.

To retheme, redefine the general variables (`--bg`, `--surface`, `--text`, `--accent`, `--border` ...) in a later `:root` rule; every component reads them.

## The rules

**Lines, not boxes.** Draw with 1px lines (`--line-hair`) over a flat ground. No shadows, no gradients, no blur. A button is text on an underline. A group of settings is just a heading and a dividing line, not a filled box. Flat layer colours from the colour table (`--surface` for a card or dialog, `--surface-top` for a top bar or table header) are fine; do not add other fills to separate sections inside a layer.

**Square.** `border-radius: 0` everywhere. Only radio buttons, rings and dots are round. (`--radius-hairline`, 2px, exists only because the source mod used it on small badges; Skald's own badge is square.)

**Pale, not gold.** The accent (`--accent`) is a pale line colour, not gold or blue. The selected tab, selected option, main button, checkbox, and progress bar all use it.

**Quiet colour.** The only hues are the status colours (`--success`, `--warning`, `--error`, `--danger`) and the five category colours (`--category-1` to `--category-5`). Use them for text and small marks, never for large fills.

**Never colour alone.** Every status has a word ("Done", "Error"). Every category colour has a name or a shape. Every selection has a line or a mark as well as a tint.

**Flat for speed.** In-game HTML UIs are often painted on the CPU. Avoid `box-shadow`, `filter`, `backdrop-filter`, gradients and animation on large areas.

### Colour roles

| Use | Variable |
| --- | --- |
| Page ground | `--bg` |
| Cards, dialogs, dropdowns (always with a `--border` line) | `--surface` |
| Deepest layer: sidebars, empty screens | `--surface-deep` |
| Top bar, table header row | `--surface-top` |
| Body text | `--text` |
| Secondary text, descriptions | `--text-muted` |
| Titles, the chosen item, entered values | `--text-strong` |
| Accent: main button underline, checks, progress, chosen tab line | `--accent` |
| Decorative frames: panels, cards, table rows | `--border` (2.1:1, never the only edge of a control) |
| Edges of inputs, selects, segmented toggles | `--border-control` (5.6:1) |
| Edges of checkboxes and radio buttons | `--accent` (11.9:1) |
| Hover / chosen tab / chosen option backgrounds | `--wash-08` / `--wash-14` / `--wash-16` (low contrast: always add a line or mark) |
| Input and well backgrounds | `--well` |
| Dialog backdrop | `--scrim` |
| Keyboard focus | `--focus`, `--line-focus` (2px), 2px offset |

All text colours meet a contrast ratio of at least 4.5:1 on every Skald background (the lowest pair is 7.9:1). Keep it that way: do not put `--text-muted` or lighter text on a new, lighter background. Disabled controls are drawn at 40% opacity and are below that on purpose; WCAG exempts disabled controls, but never use a disabled look for anything the player still needs to read.

### Type

- One family: `--font-skald` (Windows' Bahnschrift SemiCondensed, falling back to Futura Condensed, Roboto Condensed, Arial Narrow). No font file is included. Code and paths use `--font-mono`.
- Roles (also as classes `.sk-type-<name>`): `h1` 30.4px capitals, 5px tracking; `h2` 16px/500 capitals, 2px tracking; `h3` 15.2px capitals, 2px tracking; `label` 15.2px/500; `body` 16px; `body-sm` 13.6px; `caption` 12px; `code` 13px mono.
- Use uppercase only for page titles, section titles, tabs, top-bar links, table headers, and status labels; always via `text-transform: uppercase`, never typed in all caps (so translations can disable it).
- Nothing smaller than 12px.
- In-game note: Ultralight may not see Windows' Bahnschrift. If the font falls back in game and the author wants an exact match, ship a licensed font file with the mod (Roboto Condensed is Apache-2.0), declare it with `@font-face`, and list it first in `--font-skald`.

### Spacing

`--space-1` 2px, `--space-2` 4px, `--space-3` 8px, `--space-4` 12px, `--space-5` 16px, `--space-6` 24px, `--space-7` 32px, `--space-8` 48px. Padding is 8px x 14px for buttons, 6px x 10px for inputs, 12px x 8px for setting rows, and `--space-5` for cards, with `--space-6` between sections. Panels and dialogs have a double frame: a 1px outer border and a second 1px line inset by `--space-tooling` (5px).

## Components

| Component | Markup |
| --- | --- |
| Button | `<button type="button" class="sk-btn">Save</button>`; main: add `sk-btn--primary` (one per screen); destructive: `sk-btn--danger` |
| Segmented toggle | `<div class="sk-seg" role="group" aria-label="…"><button type="button" aria-pressed="true">…</button>…</div>` (2 to 4 options) |
| Text field | `<div class="sk-field"><label class="sk-label" for="x">Name</label><input class="sk-textfield" id="x"><span class="sk-help">…</span></div>`; error: `sk-field--error` on the field, `aria-invalid="true"` on the input, `<span class="sk-error-text">` with what to fix; multi-line: `sk-textarea`; required: `<span class="sk-required">required</span>` in the label |
| Select | `<select class="sk-select">` inside an `sk-field`. Native select only. When you design a new control, use a segmented toggle for 2 to 4 options and a select for more; when restyling, keep whatever control the mod already has |
| Checkbox | `<label class="sk-check"><input type="checkbox"> Label</label>` (square, like SkyUI's MCM) |
| Radio | `<fieldset><legend class="sk-label">…</legend><label class="sk-radio"><input type="radio" name="g"> …</label>…</fieldset>` |
| Tabs | `<div class="sk-tabs" role="tablist"><button type="button" class="sk-tab sk-tab--lg" role="tab" aria-selected="true" aria-controls="p1">…</button>…</div>` plus `role="tabpanel"` panels |
| Top bar | `<header class="sk-topbar"><span class="sk-brand">Name</span><nav aria-label="…"><a aria-current="page">…</a>…</nav></header>` |
| Setting row | `<section class="sk-section"><h2 class="sk-heading">…</h2><div class="sk-setting"><div><label class="sk-label">…</label><span class="sk-help">…</span></div>CONTROL</div>…</section>` |
| Table | `<div class="sk-table-wrap"><table class="sk-table">`; numbers `class="num"`; empty / loading / failed: one `<td colspan class="sk-table-state">` row |
| Badge | `<span class="sk-badge">v1.6</span>`; status: `sk-badge--success|warning|error`, always with a word |
| Notice | `<div class="sk-notice sk-notice--success|warning|error|info" role="status"><b>Done</b><span>…</span></div>` (`role="alert"` for errors) |
| Progress | `<div class="sk-progress"><div class="sk-progress-label"><span>…</span><span>64%</span></div><div class="sk-progress-track" role="progressbar" aria-valuenow="64" aria-valuemin="0" aria-valuemax="100"><div class="sk-progress-bar" style="width:64%"></div></div></div>` |
| Dialog | `<dialog class="sk-dialog">` opened with `showModal()`, or `.sk-scrim > .sk-dialog[role=dialog][aria-modal=true]`; inside: `.sk-dialog-header` (h3 + `.sk-close`), `.sk-dialog-body`, `.sk-dialog-footer` (cancel, then the main action at the far right) |
| Tooltip | `<div class="sk-tooltip" role="tooltip"><strong>Title</strong>text</div>`, linked with `aria-describedby` |
| Panel | `<section class="sk-panel sk-root">` with `.sk-panel-header` (`.sk-title` + actions) and `.sk-panel-body`; cards `.sk-card` |
| Corner ornaments | inside a panel at least 480px wide and tall: four `<img class="sk-corner sk-corner--tl|tr|bl|br" src="assets/corner.png" alt="">`; keep content 64px in from the sides |

`demo.html` shows each one with real content. Copy from it. (SchoolTabs and SchoolMarks are Heart of Magic examples; for tabs, copy Tabs, which has the panels and keyboard handling.)

The CSS styles every state (hover, selected, focus, error, read-only, disabled). Interactive behaviour belongs to the mod's code: arrow-key navigation between tabs, trapping focus in an open dialog and restoring it on close, pressing Escape to close, and positioning tooltips. CSS does none of it. When you are only restyling, do not add behaviour unless the user asks; list what is missing in your report instead.

### When restyling would change the mod's text or behaviour

The rule "change only the look" wins over Skald's other rules. In particular:

- A notice or progress bar without a status word or a number: keep the mod's text as it is, style it (`.sk-notice` with the status colour on the text), and tell the user that Skald asks for a status word or a number.
- A `<button>` with no `type` inside a `<form>` submits the form. Do not change what a button does: give it `type="submit"` to make that explicit, or `type="button"` only when the mod's code clearly handles the click itself and never relies on submitting. If you cannot tell, leave the type alone and say so.
- Tabs or toggles built from `<div>`s: style them, but do not turn them into buttons unless the user asks.

## In-game engine notes

PrismaUI and other in-game HTML UIs run on Ultralight, not a desktop browser. Not checked against Ultralight, so confirm in game:

- `:focus-visible` (Skald's focus ring). If the focus ring never shows, add the same outline to `:focus`.
- `appearance: none` on checkboxes, radio buttons and selects. If they still look native, the engine ignores it.
- The native `<select>` popup and `<dialog>` element may look or behave differently.
- Image and stylesheet paths must stay inside the folder the UI is served from; do not link to `../` outside the mod's view folder.
- The font (see Type).

## Before you finish

Check each item and report the result to the user:

- [ ] `skald-tokens.css` loads before `skald.css`, and both after the mod's own stylesheets.
- [ ] The UI's outer element has `sk-root`.
- [ ] No Skald hex colours are hard-coded in the mod's files; only `var(--…)` variables are used.
- [ ] No `border-radius` above 0 except radio buttons and rings; no shadows or gradients added.
- [ ] Every `<button>` you added or rewrote has an explicit `type`, and no existing button does something different than before.
- [ ] The mod's own classes and IDs are still on their elements.
- [ ] Inputs and selects use `--border-control`, not `--border`.
- [ ] Every status colour has a word next to it; every chosen tab or option has its line.
- [ ] Titles are capitalised via `text-transform`, not typed in all caps.
- [ ] The mod's text, logic, IDs and data attributes are unchanged unless the user asked; only the look changed.
- [ ] Anything you could not verify (how it looks in game, or font rendering in Ultralight) is listed for the user.
